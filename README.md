# 旅行产品宣传用时的配对证据与适用区间

内容团队复核出行产品的时间文案。记录覆盖交车之前和返程结束之后的旅客时间。
本仓库在原始合成资料之上提供一个可反复使用的证据工具：编辑提交候选文案的
时间门槛、出发/回程条件与旅客场景，工具在同条件的传统租车对照下给出可证实
的结论、敏感性与覆盖边界，并支持发布席的定向投放判定与更正后的复查。

## 资料和运行环境

`data/` 提供本地合成业务资料。各业务文件为 UTF-8 JSON 数组，键、单位和关联见
[资料字典](data/README.md)。`format.json` 记录列集合和基础引用约束。

使用 Python 3.11。安装锁定的分析依赖：

```sh
python3 -m pip install -r requirements.txt
```

检查资料与工具：

```sh
python3 -m unittest discover -s tests -v
```

业务原始记录允许保留冲突、未决关系及尚未到达的观察；工具不修改原始 JSON。

## 证据口径（工具如何避免“各取最有利一列”）

1. **联合可行时间**：真实分钟 = 设备钟面分钟 + 设备钟差；同一设备同一日共用
   一个未知钟差。工具把钟面区间、校准区间与相邻事件顺序
   （到交车点 ≤ 可启程 ≤ 结束游览 ≤ 可离开）写成差分约束，用 Floyd-Warshall
   求全源最短路径，得到每个事件真实时刻和每段用时的**可证实最紧区间**。
   同设备事件的钟差在差值中自动抵消；记录互相冲突（负环）时判为不可行。
2. **起止定义**：去程用时 = 旅客抵达可接受交车点 → 可以启程；回程用时 =
   结束行程 → 旅客可自行离开。全程交车用时为两段之和，在同一模型内联合求解，
   不把两段独立区间简单相加。
3. **未结束不封口**：缺“可离开”的经历（如 M081、M291）保留去程区间，但回程、
   全程与返程缓冲不得由最后一条上报自动封口。
4. **缺记录不是正证**：只含准时行程的感受调查、关闭期间的缺记录由
   `evidence_tool.external_signals` 显式筛查，只能进覆盖说明。
5. **公平对应**：出行日、交车窗、往返距离、归还方式、点位、版本、人数逐对核对，
   不能对应的差异（含“班窗可能偏移”）写入覆盖说明，不静默丢弃。
6. **截止日复放**：事件与校准按 `--as-of` 只取当时可见的最高修订，可复放
   收到更正前/后的结论。

## 两类文案的评估

* **典型时间节省**：输出同旅程权重下的配对净节省分布（逐对区间，不是单一
  平均值），并给出三种匹配误差口径——保守（区间下界达门槛）、名义（中点达
  门槛）、乐观（区间上界达门槛）；敏感性同时包含缺观察归队包络、加权 Wilson
  区间与固定种子的加权自助。通过判据采用保守口径的置信下界，保证对钟差与
  钟面不确定性稳健。
* **最短返程缓冲**：缓冲 = 表列接驳发车 − 旅客可离开时刻。去程（10 时前能
  启程）与回程缓冲在**同一行程**上联合判定，不拼接分别最稳的半程；迟尾用
  最小可保证缓冲及其分位数刻画，份额按配对权重加权。

两类结论都带覆盖说明：证据实际支持到哪些窗口、点位、归还方式、距离、版本与
地区。细分通过不得推广到总体；文案收窄场景后不能继续投到原群体。

## 命令行用法

```sh
# 全量评估（取全部可见修订）：逐旅程可行性、配对净节省、文案结论、投放判定
python3 run_evidence.py evaluate --data data --out report_full.json

# 按截止日复放（例如只使用 2026-06-12 当天可见的资料）
python3 run_evidence.py evaluate --data data --as-of 2026-06-12 --out report_old.json

# 只看配对净节省或逐旅程可行性
python3 run_evidence.py pairs --data data
python3 run_evidence.py journeys --data data

# 编辑提交候选文案（模板见 examples/candidate_statement.example.json）
python3 run_evidence.py candidate --data data \
    --candidate-file examples/candidate_statement.example.json

# 收到更正后复查现用页面：结论为什么变化，而不是只换一张平均时长表
python3 run_evidence.py review --before report_old.json --after report_full.json
```

## 投放与复查规则

发布席把文案适用范围与页面定向一并交给工具（`publish` 模块）：

* 证据覆盖必须包住路由的实际访问地区，否则不能投；
* 共享推广位且不能展示例外（`show_exceptions=false`）时，只能换成覆盖全部
  访问范围的文案，或退回编辑调整位置；能展示例外的位置允许“收窄”并提示例外；
* 内容可按地区拆分投放；`pages.json` 的 `accepted` 保留合作方已用原文的回查
  线索；
* `review` 对每条现用路由给出“站得住 / 收窄 / 先停投 / 退回调整位置”的前后
  对比，并列出通过状态、覆盖地区、关键份额或迟尾缓冲的具体变化与原因。

## 代码结构

| 模块 | 职责 |
| --- | --- |
| `evidence_tool/records.py` | 资料装载、截止日修订选择 |
| `evidence_tool/engine.py` | 差分约束模型、联合可行区间、冲突与开放经历判定 |
| `evidence_tool/matching.py` | 候选配对可比性核对、配对级净节省区间 |
| `evidence_tool/sensitivity.py` | 加权份额、Wilson、加权自助、缺观察包络 |
| `evidence_tool/claims.py` | 两类文案的证据评估与覆盖边界 |
| `evidence_tool/publish.py` | 推广位定向、覆盖冲突、更正复查 |
| `evidence_tool/external_signals.py` | 感受调查与关闭期缺记录筛查 |
| `run_evidence.py` | 命令行入口 |
| `tests/` | 单元测试（含与线性规划参考实现的交叉验证） |
